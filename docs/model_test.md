下面是一套**以单张 RTX 3090、约两周时间盒为目标的完整快速测试方案**。它用于决定是否投入正式研究，不用于直接支持投稿结论。

核心原则是：**先确认数据能体现目标问题，再验证奖励是否可靠，最后检查后训练是否带来独立于“多训练”的收益。每阶段允许“通过、修正、证据不足”，不把一次配置失败直接判为 idea 失败。**

---

**统一实验配置先固定，避免测试过程中不断改变问题。**

| 项目 | 快速实验设置 |
|---|---|
| 数据 | SpaceNet 3 的一个城市，优先从 AOI 2 Vegas 开始 |
| 划分 | 约 400 个训练裁块、60 个开发裁块、40 个最终留出裁块 |
| 空间隔离 | 按原始影像／地理区域划分后再裁块，避免邻近或重叠泄漏 |
| 分辨率 | 原尺度 256×256；若缺少有效拓扑结构，改用少量 512×512 |
| 生成器 | 预训练 ResNet-18 图像编码器＋小型条件速度场 UNet |
| 训练方式 | 固定裁块；不使用随机裁剪 |
| 主评价 | Dice、BF1、中心线 precision、采样路径奖励、官方 APLS |
| 推理 | 单候选；重复采样只报告均值与波动，不进行集成或择优 |
| 随机性 | 初筛单次训练；关键 checkpoint 使用 3 个固定推理种子 |
| 暂不开展 | 第二数据集、全套外部对比、多城市交叉验证、完整多训练种子实验 |

这里的裁块数量是规模参考。**空间独立性比凑够数量更重要**，多个相邻裁块不能被当作多个独立区域。

三个集合的用途严格分开：

- **训练集：**FM 预训练、蒸馏候选生成、GRPO。
- **开发集：**调参、H1 诊断、checkpoint 选择。
- **最终留出集：**快速实验结束后统一确认，不用于任何训练或选择。

---

**先做“数据适用性检查”，确认小实验没有把研究现象裁掉。**

在训练前统计：

| 检查量 | 目的 |
|---|---|
| 每块有效路径查询数 | 避免大量没有可评价路径的裁块 |
| 路径长度分布 | 判断是否只有极短局部道路 |
| 交叉点、连通分量、环路分布 | 判断是否存在结构性差异 |
| 完整可见路径比例 | 排除绕出裁块的不可观察路径 |
| 空道路、单一直路、复杂路网比例 | 判断样本是否过于简单 |

开发集同时包含普通路段与结构较复杂的区域，不能只挑容易样本，也不能全部挑疑难样本。

**继续条件：**存在足够的交叉点、分支、绕行或容易断连的结构，可以构造有效路径查询。

**不满足时：**先调整裁块尺度或空间样本。若 256 主要包含直路，使用少量 512 裁块，即使减少 batch，也比在没有拓扑现象的数据上测试更有意义。

---

**第 0 阶段只验证奖励，不训练模型。**

固定矢量化流程：

> 阈值化 → 骨架化 → 图构建 → 交叉点聚合 → 度为 2 节点压缩 → 路径评价。

不做闭运算补路、跨间隙连边或 A* 修复。

主奖励保持：

\[
R=
0.5R_{\mathrm{path}}
+0.2P_{\mathrm{centerline}}
+0.2\mathrm{Dice}
+0.1\mathrm{BF1}.
\]

这是初始固定配方。第 0 阶段首先验证每个分量，再检查总奖励是否给出合理排序，不能只看总分。

路径项使用：

\[
r_q=
\begin{cases}
0,&\text{匹配失败或预测不可达},\\[3pt]
1-\min\left(1,\frac{|\hat d_q-d_q^*|}{d_q^*+\epsilon}\right),
&\text{其他情况}.
\end{cases}
\]

控制点包括端点、交叉点和道路中间点。GT 查询池离线缓存，训练时从池中抽取；同组候选共享查询。

| 测试 | 应观察到的行为 |
|---|---|
| 非空 mask 与自身比较 | 有效查询分数在浮点容差内为 1 |
| GT 图栅格化后再提图 | 误差来源可解释，不强制接近 1 |
| 删除关键道路片段 | 路径分下降 |
| 增加额外支路 | 中心线 precision 下降 |
| 加宽道路 | Dice／BF1 下降 |
| 平行道路短接 | 部分相关查询出现异常缩短，同时记录漏检 |
| 改变图节点拆分 | 路径结果基本不变 |
| 空图、孤立点、无有效查询 | 处理明确，无虚假满分 |
| 相近质量候选反复抽查询 | 优劣排序基本稳定 |

额外比较 **24／48／96 条查询**，观察：

- 同组候选奖励差值的波动；
- 候选排序翻转情况；
- 按奖励选出的候选在官方 APLS 上是否更好；
- 奖励耗时。

不设未经验证的统一相关系数门槛。选择成本可接受、排序稳定的查询数，预计从 48 开始。

**继续条件：**奖励能区分与任务相关的错误，并能在相近质量候选之间提供可靠比较。

**失败处理：**暂停后训练，修验证器。此时只能得出“验证器尚不可用”。

**第 1 阶段训练一个可用底座，并确定采样配置。**

使用前面已确定的条件 FM：

\[
y=2M^*-1,\quad
x_t=(1-t)y+tz,\quad
v^*=z-y.
\]

预训练采用 FM 损失和固定的 soft-Dice 辅助项。底座配置确定后，不再为不同后训练方法重新调整。

另训练一个同编码器、相近解码器规模的判别式 UNet，用于判断生成底座是否明显偏弱。它是诊断参照，不要求 FM 在快速阶段达到同等效率。

训练设置采用：

- 固定最大更新预算；
- 固定验证间隔；
- 根据开发曲线判断是否进入平台期；
- 底座选择依据同时包含区域质量和可评价的道路结构。

“训练几千步”是预算起点，不等于已收敛。

底座完成后做有限采样扫描：

| 扫描 | 做法 |
|---|---|
| ODE 步数 | 8／16／32 步 |
| SDE 噪声 | 固定步数，比较低、中、高三个强度 |
| 结构噪声 | 短末端分支密度、小连通域面积比例 |
| 计算成本 | 单候选和 16 候选的耗时、峰值显存 |

选择一个固定的主采样器和步数，供后续底座、B1、B3、GRPO 公平评价。H1 诊断必须覆盖准备在 GRPO 中使用的 SDE 配置。

**继续条件：**

- 输出具有可辨识、可评价的道路结构；
- Dice／BF1 达到事先规定的基本要求；
- 有足够的有效匹配和可达查询；
- 候选差异不主要来自椒盐噪声或数值误差；
- 计算成本可承担。

**失败处理：**修底座或采样器。不能据此否定路径后训练。

---

**第 2 阶段检验 H1：几何合格的候选中是否存在可利用的拓扑差异。**

只在开发集做诊断，每张影像生成 16 个候选。

使用冻结底座和独立固定种子的少量参考采样，得到单图参考 Dice、BF1。预先定义合格集合：

\[
\mathcal E(I)=
\left\{
i:
D_i\ge D_{\mathrm{ref}}(I)-\delta_D,\;
B_i\ge B_{\mathrm{ref}}(I)-\delta_B
\right\}.
\]

几何容忍量在查看候选选优结果前确定。可暂以 Dice 下降不超过 0.5 个百分点、BF1 下降不超过 1 个百分点作为开发起点，但需结合标注与测量波动确认，不能为了制造 oracle 差距事后放宽。

每图记录四个量：

| 量 | 含义 |
|---|---|
| 合格率 | 几何质量允许的候选有多少 |
| 合格候选平均 APLS | 当前正常采样水平 |
| 合格候选 oracle APLS | 候选池中可见的最好拓扑 |
| 奖励选优后的 APLS | 验证器实际上能否找到更好的候选 |

合格候选不足两个时不计算内部差距，报告其比例。按简单道路、复杂路口、疑似遮挡区域等分别查看，避免总体平均掩盖现象。

**通过：**合格候选中存在稳定的拓扑差异，而且按训练奖励选优在官方 APLS 上获得正向收益。

**需要复核：**差距小、合格率低或排序不稳定。先区分：

- 底座已经接近当前子集上限；
- 所有候选都很差；
- 候选缺少结构多样性；
- 查询或评价噪声过大；
- 裁块太小、场景太简单。

只允许一次有针对性的修正，例如调整噪声或补充少量较大裁块。修正后仍无信号，记录为**当前配置未暴露可利用空间**，暂停扩大投入。

这一阶段不新增训练，但包含候选生成和官方评价成本。

---

**第 3 阶段用筛选蒸馏做低成本探测，但不把它设为 GRPO 的硬门槛。**

候选必须在**训练集重新生成**，不得使用第 2 阶段的开发集候选。

每张训练影像生成固定数量的候选。筛选范围先限制在几何合格集合中；没有合格候选时，各蒸馏组统一回退到 GT，并记录回退比例。

进行三个短程对照：

| 方法 | 训练目标 |
|---|---|
| B1：继续监督训练 | 原始 GT |
| B3：奖励筛选蒸馏 | 合格候选中总奖励最高者 |
| B3-random：随机候选蒸馏 | 同一合格候选池中随机选择 |

三者使用相同底座、可训练参数、优化器更新数和影像批次安排。为与最小 GRPO 对齐，均冻结图像编码器。

不限定“只训练一轮”。采用几个固定检查点，例如总预算的 \(1/3、2/3、1\)，查看是否存在学习趋势。只在开发集选 checkpoint。

| 结果 | 解释 |
|---|---|
| B3 优于 B1 和随机选择 | 奖励筛选具有可学习价值 |
| B3 优于随机选择，但不优于 B1 | 筛选有效，但尚未超越额外 GT 监督 |
| B3 与两者持平 | 证据不足，不能否定 GRPO |
| APLS 提高、几何退化 | 存在取舍，尚未达到目标 |

如果第 2 阶段的信号明确，即使 B3 持平，也继续做最小 GRPO。离线伪标签拟合失败不意味着策略优化没有潜力。

---

**第 4 阶段运行最小 GRPO，直接检验研究主张。**

| 项目 | 设置 |
|---|---|
| 初始化 | 与 B1、B3 相同底座 |
| 更新范围 | 冻结编码器，仅更新速度场 |
| 候选数 | \(G=4\) 调试，信号明确但不稳定时追加一次 \(G=8\) |
| 采样器 | 第 1 阶段确定的 SDE |
| 步数 | 固定为 8 或 16，不能随 checkpoint 改变 |
| 奖励 | 固定四项奖励，候选共享查询 |
| 正则 | 参考底座 KL |
| 学习率 | 从 \(10^{-5}\) 附近起步 |
| 更新预算 | 几百次优化器更新起步，按实测成本设置上限 |
| 验证 | 固定间隔，官方 APLS 仅在预定节点运行 |

更新前必须通过：

- 相同策略、相同轨迹重算概率比接近 1；
- 状态、时间表、方差和 old log-prob 一致；
- KL 计算和空间归约一致；
- 低方差组不会被数值噪声放大；
- 不把确定性转移当作普通随机转移计算概率比。

最少记录以下曲线和统计：

| 类型 | 内容 |
|---|---|
| 目标表现 | 训练奖励、开发集独立查询奖励、官方 APLS |
| 几何表现 | Dice、BF1、中心线 precision、合格率 |
| 优化状态 | KL、clip fraction、组内奖励标准差 |
| 难度覆盖 | 全高同分组、全低同分组比例 |
| 对照 | 同更新预算 B1 的 APLS 与几何表现 |

出现问题时根据诊断调整一个变量，不做全面搜索：

- 奖励不变：检查是否有可用优势、参数是否更新及概率比实现。
- 奖励涨、APLS 不涨：检查训练过拟合、查询覆盖、采样器一致性和评价误差。
- 几何退化：检查质量奖励、KL 和候选合格率。
- 先涨后崩：结合 KL、clipping 和奖励分布定位，不直接归因于某一个超参数。

允许**一次有依据的修正运行**。例如 \(G=4\) 明显不稳定且候选信号充分，再试 \(G=8\)。超过预设排查预算仍没有收益，结论是“当前后训练配方证据不足”。

---

**最后做一次未调参区域上的确认，决定是否投入完整实验。**

在开发阶段结束后，冻结：

- 模型 checkpoint；
- 采样器和步数；
- 阈值与矢量化参数；
- 奖励和几何门槛；
- 比较方法及评价种子。

在最终留出集评价：

- B0：底座；
- B1：继续监督训练；
- 开发集最好的奖励驱动方法；
- GRPO，如果它不是上一项。

每个模型使用相同的 3 个固定推理种子，分别计算单候选结果。对同一影像进行配对比较，按原始大图／区域聚合，不把大量路径当成独立样本。

**值得进入正式实验的条件：**

1. APLS 相对 B0 和 B1 有一致改善；
2. Dice／BF1 在预设容忍范围内；
3. 改善不依赖一个推理种子或极少数裁块；
4. 原始案例确实表现为断路、绕行或额外道路减少；
5. 时间和显存成本能够扩展到正式规模。

若只有蒸馏改善，支持“验证器驱动的后训练值得继续”，尚不支持“GRPO 更优”。

最终留出结果不理想时，不在该集合上继续调参后仍称其为独立测试。

---

**缓存和预算管理只保留不会改变实验含义的加速措施。**

可以缓存：

- 固定裁块和 GT 图；
- 控制点、较大的查询池及 GT 路径长度；
- 固定参考模型的几何指标；
- 冻结编码器在固定输入下的特征。

不能复用：

- 编码器更新后的旧特征；
- 与颜色增强后输入不一致的特征；
- 与新裁块范围不一致的路径缓存。

64 图过拟合只做一次实现检查，成功后恢复正常空间划分。不要每一关都过拟合，否则会改变候选差异和泛化问题。

时间安排作为上限而非完成承诺：

| 工作 | 建议时间盒 |
|---|---:|
| 数据检查＋验证器 | 2–3 天 |
| 底座＋采样扫描 | 2–3 天 |
| H1 诊断 | 约 1 天 |
| 短程蒸馏对照 | 1–2 天 |
| 最小 GRPO＋一次排查 | 3–4 天 |
| 留出确认与报告 | 约 1 天 |

先实测一次 rollout、奖励和更新耗时，再确定更新上限。预算耗尽但曲线仍在变化，应报告“未完成判断”，不强行判为失败。

最终只需要产出四份结果：**验证器测试表、合格候选诊断图、B0/B1/蒸馏/GRPO 对比表、留出集确认与成本记录。**它们足以回答下一步该扩大实验、修正某一环节，还是暂缓当前路线。
